# Platform capability and Event Marketing readiness

Updated through WP1M, 2026-10-07. Public automation support and Event Marketing access are separate evidence questions. **CONFIRMED** means supported by the cited public documentation or explicit product policy; **UNVERIFIED** means not established for this account/integration; **MANUAL** is the required human execution policy; **EXCLUDED** is outside V1. Meetup schema fields were checked through anonymous read-only introspection; no Meetup account credentials, permissions, or live write behavior were tested. LinkedIn's current Marketing API and OAuth contracts were checked against official docs; no Event Marketing OAuth, Community Management approval, Page role, or real write was tested. Instagram Login and the v26.0 account/publishing contract were checked against current Meta documentation; no Event Marketing app credentials, OAuth grant, app review/access, public media host, or live write was tested. WP1M adds encrypted OAuth persistence and test-only fake authorization flows but does not verify production account access. Candidate facts below are architectural relevance examples, not complete verified API schemas.

Execution kind AUTO/MANUAL, integration readiness UNVERIFIED/READY/BLOCKED, and runtime mode SIMULATED/LIVE are independent; see [contract](connector-contract.md). The backend derives AUTO modes from trusted server settings before approval and freezes them in the destination plan; the browser cannot select them. Current defaults are SIMULATED for Eventbrite, Meetup, LinkedIn organization, and Instagram; Facebook Groups is fixed MANUAL. Eventbrite, Meetup, LinkedIn Organization, and Instagram have LIVE adapter implementations, but Event Marketing account access remains unverified; LIVE is never enabled by credentials alone. LinkedIn additionally requires member OAuth credentials and suitable Community Management approval before production readiness. Instagram requires Instagram Login, a verified eligible Professional account, publishing permission, and public HTTPS media delivery; the app has no approved encrypted credential store or OAuth connection flow yet. READY in simulation makes no claim about LIVE access. Portal has no execution kind assigned until understood. Explicitly excluded targets can appear as informational review context, but never as included publishing work.

## Public-platform evidence and limits

1. [Eventbrite Creating an Event](https://www.eventbrite.com.au/platform/docs/create-events) documents event creation, ticket-class creation and publication. A generic event record alone is not publish readiness: ticket classes are part of that flow. The indexed official content was available; direct page retrieval returned HTTP 429. Full current publish validation and paid-payment prerequisites remain to be verified before LIVE implementation; do not infer account readiness.
2. [Meetup GraphQL guide](https://www.meetup.com/graphql/guide/) shows createEvent with a DRAFT status and editEvent to publish. Example inputs include group, title, description, start, venue and duration. Examples establish operations, not every conditional schema requirement or Event Marketing authorization.
3. [LinkedIn Posts API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api?view=li-lms-2026-09), [Marketing API versioning](https://learn.microsoft.com/en-us/linkedin/marketing/versioning?view=li-lms-2026-09), [Organization Access Control](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/organizations/organization-access-control-by-role?view=li-lms-2026-09), [Images API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/images-api?view=li-lms-2026-09), and [Community Management App Review](https://learn.microsoft.com/en-us/linkedin/marketing/community-management-app-review) document organization posting with `w_organization_social`, version/protocol headers, image upload, and vetted Development/Standard tiers. The Images API links to official upload instructions specifying raw-byte `PUT` and bearer authorization. Posts API names the Content Admin posting role `CONTENT_ADMIN`, while the Organization ACL role enum is `CONTENT_ADMINISTRATOR`; until provider behavior confirms the relationship, the connector accepts only the shared exact posting-role values. This confirms conceptual automation, not Event Marketing account access, OAuth grant, Page role, tier, or live result.
4. Meta's [Instagram Login getting started guide](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/get-started), [content publishing guide](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/content-publishing), [Instagram User reference](https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-user), and [publishing limit reference](https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-user/content_publishing_limit) describe the Instagram Login API, eligible Business/Creator account types, `instagram_business_basic` / `instagram_business_content_publish`, v26.0 as the latest supported Graph version on 2026-10-07, image containers and publishing, and provider-reported quota. These facts confirm public API capability, not Event Marketing account access, token scopes, app review, or a live result. No blanket Facebook Page prerequisite is inferred across login paths.

API schemas and access requirements can change. Meetup schema/input details used by WP1J were checked through anonymous official GraphQL introspection on 2026-10-07; Event Marketing account access remains separate and UNVERIFIED until an authorized read-only smoke is run. WP1J automated tests use only a fake transport and make no Meetup API calls. Photo binary upload remains deferred because the official guide does not document its transport method/headers. LinkedIn Marketing version `202609` and Instagram Graph API version `v26.0` are current and supported as of 2026-10-07. Local/static validation before approval remains required even when remote validation is deferred. WP1M's fake OAuth flows and encrypted storage do not establish real LinkedIn/Instagram account access, app review, or permission grants.
